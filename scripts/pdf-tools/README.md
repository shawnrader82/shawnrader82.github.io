# PDF Tools

## fix-poa-acroform.py

Repairs the CA Statutory POA PDF via full Ghostscript rebuild while preserving all 17 original form widget positions and field names.

## Root cause

The website's fillable POA PDF was originally generated by ReportLab, then hand-edited in Foxit at some point. That Foxit edit left behind structural artifacts that Brave's PDFium print engine refused to process — most visibly a print job that warmed up the printer then aborted on page 3, delivering only pages 1 and 2.

Contributing factors identified during investigation:
- **Foxit-private fonts** on page 3 only (`/FXF1`-`/FXF4`) whose internal `/Name` entries mismatched their resource dictionary keys
- **Degenerate text matrix** on page 3: `0 0 0 1 332.762 129.497 Tm` (determinant zero)
- **Orphan widget annotations** on pages 2-3 not registered in `/AcroForm /Fields`

Non-strict PDF viewers (Chrome, Firefox, Adobe Reader, Foxit, Nextcloud PDF viewer, iOS Safari) all silently worked around these issues. Brave's PDFium in strict mode did not, and print jobs failed at page 3.

Surgical fixes (v1 and v3 of this script) addressed each issue in isolation but did not resolve the print failure — indicating cumulative structural damage beyond individually-identifiable defects.

## What the script does (v4 — nuclear rebuild)

1. **Extract widget metadata** from source PDF: field name, type, rect, flags, max length, etc. for every widget on every page.
2. **Rebuild via Ghostscript** with `pdfwrite` device at `/prepress` quality and PDF 1.7 compatibility. This fully re-renders content streams and writes a brand new PDF structure — no Foxit contamination, standard fonts, valid content streams throughout.
3. **Re-add widgets** at their exact original coordinates with their original field names, invisible borders (`border_width=0`), Helvetica 10pt text, and print flag F=4. This preserves customer-visible field labels ("your name and address", "Agent 1", etc.) and Foxit iOS/Android tappability.
4. **Idempotent** — safe to run repeatedly on the same file.

## Usage

```bash
pip install pymupdf pypdf
apt-get install ghostscript
python3 scripts/pdf-tools/fix-poa-acroform.py input.pdf output.pdf
```

## Verification

```bash
# Ghostscript sanity — should be silent (no repaired/warning/error output)
gs -o /dev/null -sDEVICE=nullpage -dNOPAUSE -dBATCH \
  assets/forms/ca-statutory-power-of-attorney.pdf 2>&1 \
  | grep -iE 'error|warning|degenerate|repaired' || echo 'Clean'

# qpdf sanity
qpdf --check assets/forms/ca-statutory-power-of-attorney.pdf 2>&1 | tail -5

# Field names + count
python3 -c "
from pypdf import PdfReader
r = PdfReader('assets/forms/ca-statutory-power-of-attorney.pdf')
f = r.get_fields()
print(f'Named fields: {len(f) if f else 0}')"
# Expected: 16 named fields (one unnamed for the "seal" spacer)

# Producer
pdfinfo assets/forms/ca-statutory-power-of-attorney.pdf | grep -E 'Producer|Form|JavaScript'
# Expected: Producer: GPL Ghostscript, Form: AcroForm, JavaScript: no
```

## When to run

- After any manual PDF edit in Foxit or Adobe Acrobat that touches the fillable form
- After any ReportLab regeneration of the POA
- Any time customer prints of this document fail on any specific page in any specific browser
